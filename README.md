# Генерация карточки товара

Локальный сервис для контент-менеджера B2B-магазина контрольно-измерительных приборов. На вход — данные прибора (JSON или веб-форма), на выход — черновик карточки:

- SEO-заголовок до 70 символов;
- SEO-описание 800–1200 символов;
- список характеристик;
- 3–5 поисковых запросов;
- блок для менеджера: кому подходит прибор и какие задачи решает.

Результат копируется одной кнопкой: текстом, Markdown или JSON.

Характеристики в карточку переносит код ровно из входных данных. Если значения нет, стоит «данных нет», а рядом с карточкой — подсказка «Что уточнить перед публикацией». Модель (Groq) пишет только связный текст, а код после неё вырезает всё, чего не было во входе, и показывает, что именно вырезано.

## Быстрый старт

Зависимости ставятся через [uv](https://docs.astral.sh/uv/). Python отдельно ставить не нужно: если подходящего нет, uv скачает Python 3.11 сам.

**1. Установите uv** (один раз):

```bash
# macOS и Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**2. Установите зависимости** — из корня репозитория:

```bash
uv sync
```

**3. Получите бесплатный ключ Groq:** https://console.groq.com/keys — войдите, нажмите «Create API Key» и скопируйте ключ (начинается с `gsk_`).

**4. Положите ключ в `.env`:**

```bash
# macOS и Linux
cp .env.example .env
```

```powershell
# Windows (PowerShell)
copy .env.example .env
```

Откройте `.env` и вставьте ключ после `GROQ_API_KEY=`. Файл `.env` в git не попадает.

**5. Запустите:**

```bash
uv run uvicorn app.main:app
```

Откройте http://127.0.0.1:8000. Если порт занят, добавьте `--port 8010` и откройте http://127.0.0.1:8010.

## Как пользоваться

1. Нажмите пример: «Манометр DM 02», «Датчик давления ДД-420», «Манометр DM 02 (с пропусками)» или «Некорректный JSON». Можно заполнить поля вручную или вставить свой JSON.
2. Нажмите «Собрать карточку». Ответ приходит за 5–20 секунд.
3. Откройте нужный формат (текст, Markdown, JSON) и нажмите «Копировать».

Над результатом две подсказки, в копируемый текст они не попадают: «Что уточнить перед публикацией» (или зелёная «Все поля заполнены») и свёрнутая строка «Убрано из текста модели» — что код вырезал и почему. Значок «?» рядом с заголовком страницы — короткая инструкция.

## API

`POST /api/generate` принимает JSON товара в формате из задания:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

macOS и Linux:

```bash
curl -X POST http://127.0.0.1:8000/api/generate -H "Content-Type: application/json" --data-binary @data/manometer.json
```

Windows (PowerShell): то же самое, но `curl.exe` вместо `curl` и `"@data/manometer.json"` в кавычках.

Ошибки возвращаются как `{"error": "..."}` с понятной причиной: битый JSON — 400 (для ошибок разбора есть ещё `line`, номер строки), неверный ключ Groq — 401, лимит Groq — 429, нет ключа или сети — 503. Описание маршрута: http://127.0.0.1:8000/docs

## Примеры

В задании обещаны два товара, а в тексте пришёл один — манометр из примера структуры JSON. Второй товар составлен мной в том же формате: это условный прибор, а не паспорт реального изделия.

| Вход | Что показывает | Результат |
|---|---|---|
| `data/manometer.json` | товар из задания, все поля заполнены | `examples/manometer.md`, `.json` |
| `data/pressure_sensor.json` | условный датчик давления: мА, В, IP, метрическая резьба | `examples/pressure_sensor.md`, `.json` |
| `data/manometer_incomplete.json` | неполные данные: «данных нет» и «Что уточнить» | `examples/manometer_incomplete.md`, `.json` |
| — | некорректный вход: 8 типичных ошибок и ответы на них | `examples/invalid_json.md` |

Пересобрать все примеры (нужен ключ Groq):

```bash
uv run python -m scripts.generate_examples
```

## Тесты

Сеть и ключ не нужны: вместо модели подставляется заготовленный ответ.

```bash
uv run pytest
```

## Устройство

```
app/
  main.py        форма, API, разбор входного JSON и понятные ошибки
  domain.py      модели данных и сборка Markdown
  facts.py       характеристики из входа и проверка текста на чужие значения
  prompts.py     промпт модели
  llm.py         клиент Groq и ошибки API
  generator.py   сборка карточки: ответ модели → проверка → один повтор → чистка
  templates/     страница
data/            входные примеры
examples/        готовые ответы сервиса
scripts/         генерация примеров
tests/           тесты без сети
docs/            задание, решения и ограничения, сопроводительное письмо
pyproject.toml   зависимости; uv.lock фиксирует точные версии
```

Промпт целиком, принятые решения, замер устойчивости, ограничения и идеи на потом — [docs/DECISIONS.md](docs/DECISIONS.md). Текст задания — [docs/TEST_ASSIGNMENT.md](docs/TEST_ASSIGNMENT.md). Сопроводительное письмо — [docs/COVER.md](docs/COVER.md).

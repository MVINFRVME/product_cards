Здесь лежат ответы сервиса для входов из `data/`:

- `manometer` — манометр из задания, полные данные;
- `pressure_sensor` — условный датчик давления, составленный мной, потому что второй товар в тексте задания не пришёл;
- `manometer_incomplete` — тот же манометр с пустыми полями: видно «данных нет» и «Что уточнить»;
- `invalid_json.md` — ответы на некорректный вход: пустой запрос, текст вместо JSON, обрезанный JSON, пропущенная и лишняя запятая, все поля пустые, массив, характеристики списком.

Повторить генерацию:

```
uv run python -m scripts.generate_examples
```

Нужен `GROQ_API_KEY` в `.env`. Карточки — это ответы модели плюс характеристики, которые программа собрала из входа; вручную они не правились. В конце каждого `.md` после черты — служебные пометки для контент-менеджера: что уточнить и что код вырезал из текста модели. В саму карточку они не входят. `invalid_json.md` собирается без модели: битый вход до неё не доходит.

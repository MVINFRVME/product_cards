Здравствуйте! Отправляю тестовое задание «AI-помощник для подготовки товарных описаний».

Репозиторий: https://github.com/MVINFRVME/product_cards

Скринкаст: https://cloud.mail.ru/public/SxNS/J4uSMp1VD

**Что реализовано**

- Локальный сервис на Python (FastAPI) с веб-формой и API `POST /api/generate`; вход — JSON в формате из задания.
- Карточка: SEO-заголовок до 70 символов, описание 800–1200 символов, характеристики, 3–5 поисковых запросов, блок для менеджера.
- Результат копируется текстом, Markdown или JSON.
- Пустые поля дают «данных нет» и подсказку «Что уточнить перед публикацией»; служебные подсказки в копируемый текст не попадают.
- Некорректный JSON, пустой запрос и ошибки Groq не создают карточку; сервис объясняет причину, для битого JSON подсвечивает строку.
- Примеры результатов и 8 разобранных вариантов некорректного входа — в `examples/`; 15 тестов без сети.

**Принятые решения**

- Одна модель — Groq `openai/gpt-oss-120b`; ключ только в `.env`, файл в `.gitignore`.
- Модель не отвечает за факты: список характеристик переносит код ровно из входа, модель пишет только текст.
- После ответа модели код сверяет текст со входом (числа с единицами, резьба, IP, ГОСТ, класс точности, слова вроде «взрывозащищённый» или «монтаж») и вырезает то, чего во входе нет. Вырезанное показывается отдельным списком с причиной.
- Если первый ответ не прошёл проверку, модели один раз отправляется повторный запрос с перечнем замечаний.
- Единицы измерения не угадываются: «0–1,6» без единицы остаётся как есть, «МПа» от модели вырезается.
- Если описание короче 800 символов, объём добирается фразами только из входных данных и нейтральными фразами магазина, без новых характеристик.

**С какими сложностями столкнулся**

- Модель постоянно дописывала «типичное» для прибора: монтаж, промышленные условия, газовые линии, чужие классы и резьбы. На замере (9 прогонов) первый ответ ни разу целиком не уложился в требования; итоговая карточка после повтора и проверки кодом — 9 из 9. Уточнение промпта почти вдвое сократило выдумки, но совсем их не убрало.
- Модель противоречила входу: писала «класс точности — данных нет» при переданном классе 1,5.
- Объём 800–1200 конфликтовал с запретом выдумывать: на бедном входе модель пересказывала одно и то же разными словами. Пришлось схлопывать повторы и добирать объём из фактов.
- Ловушки самой проверки: «газ» находился внутри «магазина», «2088 в» выглядело как 2088 вольт, неразрывные пробелы мешали найти фразу для вырезания.
- В тексте задания пришёл только один товар из двух обещанных. Второй — условный датчик давления — придумал сам в том же формате, это не паспорт реального изделия.
